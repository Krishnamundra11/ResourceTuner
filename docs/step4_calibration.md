## Methodology

1. **Data collection** (`scripts/collect_telemetry.py`): telemetry sampled at 1 Hz and appended to `data/telemetry_log.jsonl`, one line per second, each labelled with `state`, `scenario`, `level` and `notes`.
   * **idle** — no workload containers, in two variants: *realistic* (desktop, VS Code and this tooling open — the deployment condition) and *clean* (VS Code closed — tightest signal). Both are negatives.
   * **load** — one developer workload alone (build / tests / indexer): busy but uncontended.
   * **congestion** — a workload with a competitor, or a resource hog, at low / medium / high intensity. Each run: 15 s warm-up (PSI avg10 is a 10 s average), then 45 s recorded.
2. **Grouping.** Negatives = idle + load. **CPU positives = runs whose designed CPU demand exceeds the 6 vCPUs** (demand = build JOBS + test WORKERS + indexer replicas + hog CPU_WORKERS x CPU_LOAD, read from the scenario files). Runs that fill but do not exceed the cores (e.g. build_and_test, 3+3 threads) are *saturated, not oversubscribed*; they are reported separately. I/O and memory positives = medium/high runs of io_pressure, indexer_vs_io / ram_pressure, build_vs_ram; low-intensity runs are reported, not fitted.
3. **Threshold rule** (identical for every metric): if negative p99 < positive p5 the classes are separable and the threshold is the midpoint of those two percentiles (largest symmetric margin); otherwise the value maximising Youden's J = TPR − FPR. TPR/FPR are reported per sample.
4. **Persistence**: longest run of consecutive negative seconds above the CPU PSI threshold, with the brief's 10 s as a floor.
5. **References**: Linux PSI (`/proc/pressure`, some avg10); systemd-oomd defaults from `man oomd.conf` on this VM (systemd 259): memory pressure limit 60% for 30 s; earlyoom default minimum available memory 10% (from its documentation; not installed here).
6. **Validation**: `scripts/validate_classifier.py` re-run with the new config.

Samples: idle 960, load 135, congestion (medium/high) 765, light (low) 360; CPU-oversubscribed 360, CPU-saturated-only 495.
